# CLAUDE.md

Telegram-бот для конвертации шрифтов. Главный домен — `src/font-convertor/`;
Telegram, `User`, PostgreSQL и остальная инфраструктура обслуживают его.

## Документация

Читай под задачу, а не подряд:

- Называешь доменное понятие (заголовок issue, имя теста, имя класса) — `CONTEXT.md`.
- Правишь код — файл затронутой подсистемы в `docs/architecture/`: устройство и
  рантайм-последовательности лежат в нём же. Чей файл открыть, скажут оглавление и карта
  директорий в `docs/architecture/README.md`. Что твоя правка сделала в нём ложным —
  чини тем же PR: это не соседний код.
- Не поднимается окружение, нужны токены, compose или переменные — `README.md`.
- Заводишь или ведёшь задачу — она в GitHub Issues, операции через `gh`:
  `docs/agents/issue-tracker.md`; как скиллам читать доменные доки —
  `docs/agents/domain.md`.

## Правки документации

Дописать абзац дешевле, чем перечитать документ, — так и набегает нарост. Четыре проверки
в момент письма, каждая дешевле самого абзаца:

- **Утверждение о коде — из открытого файла**, и в тексте назван файл, символ или команда,
  по которым оно проверено. Абзац по памяти — свежая ложь.
- **Ссылка на issue — источник, а не носитель смысла.** Закрой issue мысленно: абзац
  обязан остаться верным. «Временные файлы не удаляются (issue #37)» проходит, «известная
  проблема, см. #N» — нет.
- **Дубль дороже ссылки.** Перед новым абзацем — `grep -rn <идентификатор>` по всем `*.md`
  репозитория; нашлось в другом файле или разделе — правь найденное, вторую копию не
  заводи.
- **Перечень, выводимый из кода, не заводится**: список, который печатает одна команда или
  который целиком лежит в одном файле, заменяется указанием, где смотреть. Не выводится —
  можно: непокрытое тестами из дерева `test/` не вычесть.

Правится ложь, а не стиль: ошибка садится там, где текст новый. «Почему», отвергнутый
вариант, ловушка и цена ошибки из кода не восстанавливаются — сокращать их можно, только
когда код их отменил.

## Рабочий процесс

- Каждая задача — в своём git worktree и своей ветке, результат — PR в `main`.
  Создать дерево — первый шаг, до любых правок:

  ```bash
  git worktree add "$(git rev-parse --show-toplevel)/../telegram-bot-<задача>" -b <ветка> origin/main
  ```

  Путь только абсолютный: относительный git разворачивает от своего текущего каталога.
- Код в основном дереве не правится: соседняя сессия переключит там ветку и унесёт
  незакоммиченные правки.
- После создания дерева — `make worktree-init`; после влития PR (и только после) —
  `make worktree-cleanup` в дереве задачи (её проверки и необратимость — в `README.md`,
  «Работа в нескольких worktree»). Оставленное дерево читается следующей сессией как
  задача в работе.
- Одна ветка/PR — одна задача. Перед commit — `git status -sb`. В `main` напрямую не
  коммитить: ветка защищена на GitHub.
- Документация, issues и комментарии — на русском; идентификаторы кода не переводятся.

## Команды

Только через `make`: Node и npm стоят в образе, а не на хосте, поэтому прямые `npm` и
`npx` не сработают. Список целей с описаниями печатает `make` без аргументов. Перед PR —
`make check`. Проверки `make db-reset` не обходить: база и пул токенов общие на все
деревья, сброс заденет соседние сессии.

## Scope

Минимальное изменение под задачу. Соседний код, архитектуру и попутно найденные
проблемы не трогай — про проблему сообщи или заведи issue. Новые абстракции и
многообластной рефакторинг — только по явному запросу. Следуй существующим решениям
проекта.

## Стиль

- Внутренние импорты только через `app/*` (исключение — файлы миграций).
- Новые файлы — kebab-case.
- Каталог внутри подсистемы либо прячет один файл (снаружи каталога импортируется только
  он), либо собирает однотипных братьев одного контракта; иначе файлы лежат плоско, а
  `*.types.ts` и `*.errors.ts` — рядом со своим главным. Примеры, исключения и команда
  проверки — `docs/architecture/README.md`, «Карта директорий».
- Domain не зависит от grammY, PostgreSQL и pino: список запрещённых пакетов держит
  `no-restricted-imports` для `src/font-convertor/**` и `src/shared/**` (домен берёт из
  него ошибки и утилиты) в `.eslintrc.js`.
- Голый `Error` наружу не бросается: минимум `RuntimeError` из `app/shared/errors`,
  лучше свой подкласс в `<модуль>.errors.ts` рядом с бросающим кодом. Второй аргумент —
  либо исходная ошибка (уедет в `cause`), либо объект деталей (в `payload`); нужны оба —
  ошибку кладут полем `cause` внутрь объекта.
- Комментарии — только про неочевидное: почему, а не что.

## Инварианты

Есть правила, которые код не проверяет, а нарушение ломает поведение молча. Перед
правкой читай `docs/architecture/invariants.md` — в частности, когда трогаешь пайплайн
бота и `Context`, `container.ts` и внедрение зависимостей, миграции и схему `sessions`,
поля `User`, сроки остановки, лимиты очереди, конвертор, запуск внешних процессов или
локали.

## Подпись агента на GitHub

Агент работает через `gh` от аккаунта владельца, поэтому всё, что он публикует на GitHub
(комментарии к PR и issues, ответы на inline-ревью, тела issue), заканчивается строкой:

```
_🤖 Опубликовано Claude Code от аккаунта владельца · [сессия](<ссылка на сессию>)_
```

Ссылка — та же, что в трейлере `Claude-Session` коммита. Ссылки нет — подпись без неё:
`_🤖 Опубликовано Claude Code от аккаунта владельца._`
Описания PR и сообщения коммитов подписи не требуют: у них своя пометка.
