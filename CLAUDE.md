# CLAUDE.md

Telegram-бот для конвертации шрифтов.

## Источники контекста

- `CONTEXT.md` — предметная область и терминология.
- `docs/architecture.md` — фактическая архитектура и известные технические особенности.
- `docs/flows.md` — фактические runtime-потоки.
- `README.md` — локальное окружение и команды.

Не читай всю документацию перед каждой задачей.
Сначала определи затронутую область и читай только относящиеся к ней файлы и разделы.

## Scope изменений

По умолчанию делай минимальное изменение, необходимое для выполнения задачи.

Без явной необходимости:
- не рефактори соседний код;
- не меняй архитектуру;
- не вводи новые абстракции;
- не исправляй обнаруженные попутно проблемы;
- не расширяй scope задачи;
- не читай несвязанную документацию.

Следуй существующему решению проекта, если задача не требует его изменения.

Если обнаружена отдельная проблема — сообщи о ней, но не включай исправление
в текущую задачу без необходимости.

## Правила работы

- Документация и GitHub Issues ведутся на русском языке.
- Идентификаторы кода не переводятся.
- Любое изменение делается в отдельной ветке и PR.
- Одна ветка/PR — одна логически цельная задача.
- Каждая задача ведётся в своём git worktree. Создать дерево — первый шаг задачи,
  до любых правок:

  ```bash
  git worktree add "$(git rev-parse --show-toplevel)/../telegram-bot-<задача>" -b <ветка> origin/main
  ```

  Путь только абсолютный: относительный git разворачивает от своего текущего каталога,
  и при `git -C <репо> worktree add` дерево молча ложится внутрь репозитория.
- Основное дерево — общая база и пул токенов, а не место для задач. Код в нём не
  правится даже на отдельной ветке: соседняя сессия переключит в нём ветку без
  предупреждения и унесёт незакоммиченные правки.
- Перед commit проверяй `git status -sb`.
- Не коммить и не пушь напрямую в `main`/`master`.

## Проект

Главный домен — `src/domain/font-convertor/`.
Telegram, User, PostgreSQL и прочая инфраструктура обслуживают этот домен.

Проект развивается инкрементально. Не начинай многообластной рефакторинг без явного запроса.

## Команды

Используй `Makefile` как основную точку входа:
`make up`, `make test`, `make build`, `make logs`, `make restart` и т.д.

Не запускай Node/npm напрямую на хосте — development environment работает через Docker.

`make db-reset` работает с общей для всех worktree базой и является destructive operation.
Не обходи встроенные в него проверки.

## Стиль

- Внутренние импорты только через `app/*`.
- Новые файлы — kebab-case.
- Domain не должен зависеть от grammY/PostgreSQL/pino.
- Не добавляй комментарии, описывающие очевидное поведение кода.

Для деталей архитектуры используй `docs/architecture.md`, а не дублируй их здесь.
