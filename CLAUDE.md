# CLAUDE.md

Telegram-бот для конвертации шрифтов. Главный домен — `src/domain/font-convertor/`;
Telegram, User, PostgreSQL и остальная инфраструктура обслуживают его.

## Документация

Читай только то, что относится к задаче:

- `CONTEXT.md` — термины предметной области. Читай, когда называешь доменное понятие
  (issue, тест, имя класса).
- `docs/architecture/` — по файлу на подсистему: устройство, рантайм-последовательности
  и инварианты (`invariants.md`). Оглавление — в `docs/architecture/README.md`; читай файл
  затронутой подсистемы, а не каталог целиком.
- `README.md` — окружение, worktree, токены, команды. Читай при проблемах с запуском.

## Рабочий процесс

- Каждая задача — в своём git worktree и своей ветке, результат — PR в `main`.
  Создать дерево — первый шаг, до любых правок:

  ```bash
  git worktree add "$(git rev-parse --show-toplevel)/../telegram-bot-<задача>" -b <ветка> origin/main
  ```

  Путь только абсолютный: относительный git разворачивает от своего текущего каталога.
- Основное дерево — общая база и пул токенов, код в нём не правится: соседняя сессия
  переключит там ветку и унесёт незакоммиченные правки.
- После создания дерева: `make worktree-init`. После влития PR (и только после):
  `make worktree-cleanup` в дереве задачи. Оставленное дерево читается следующей сессией
  как задача в работе.
- Одна ветка/PR — одна задача. Перед commit — `git status -sb`. В `main` напрямую не
  коммитить: ветка защищена на GitHub.
- Документация, issues и комментарии — на русском; идентификаторы кода не переводятся.

## Команды

Только через `make` (`make` без аргументов — список целей). Node/npm на хосте нет,
всё работает в Docker. Перед PR — `make check`.

`make db-reset` стирает общую для всех деревьев базу. Не обходи его проверки.

## Scope

Минимальное изменение под задачу. Соседний код, архитектуру и попутно найденные
проблемы не трогай — про проблему сообщи или заведи issue. Новые абстракции и
многообластной рефакторинг — только по явному запросу. Следуй существующим решениям
проекта.

## Стиль

- Внутренние импорты только через `app/*` (исключение — файлы миграций).
- Новые файлы — kebab-case.
- Domain не зависит от grammY, PostgreSQL и pino.
- Голый `Error` наружу не бросается: минимум `RuntimeError` из `app/common/errors`,
  лучше свой подкласс в `<модуль>.errors.ts` рядом с бросающим кодом. Исходная ошибка —
  вторым аргументом (уходит в `cause`), детали — в `payload`.
- Комментарии — только про неочевидное: почему, а не что.

## Инварианты

Есть правила, которые код не проверяет, а нарушение ломает поведение молча. Перед
правкой `Bot` и middleware, `container.ts`, миграций, конфига остановки, лимитов
очереди, логгера или локалей прочитай `docs/architecture/invariants.md`.

## Подпись агента на GitHub

Агент работает через `gh` от аккаунта владельца, поэтому всё, что он публикует на GitHub
(комментарии к PR и issues, ответы на inline-ревью, тела issue), заканчивается строкой:

```
_🤖 Опубликовано Claude Code от аккаунта владельца · [сессия](<ссылка на сессию>)_
```

Ссылка — та же, что в трейлере `Claude-Session` коммита. Ссылки нет — подпись без неё:
`_🤖 Опубликовано Claude Code от аккаунта владельца._`
Описания PR и сообщения коммитов подписи не требуют: у них своя пометка. У скиллов ревью
скрытый HTML-маркер прогона остаётся последней строкой, подпись идёт перед ним.
