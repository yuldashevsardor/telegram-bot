# Домен-доки

Как агентским скиллам читать документацию этого репозитория. Структура single-context:
`CONTEXT.md` в корне, ADR — в `docs/adr/` (каталога пока нет, он создаётся при первом
решении, которое трудно откатить; задним числом ADR не пишутся, об отсутствии каталога
не сообщать).

## Порядок чтения

1. `CONTEXT.md` — глоссарий предметной области: конвертация шрифтов, форматы, пары.
   Только термины, без устройства кода.
2. `docs/architecture/` — устройство кода, рантайм и инварианты, по файлу на подсистему.
3. `docs/adr/` — решения по области, которую правите, когда каталог появится.

## Словарь глоссария

Называя доменное понятие (заголовок issue, имя теста, предложение по рефакторингу),
используйте термин из `CONTEXT.md`, не синоним. Понятия нет в глоссарии — либо вы
придумываете язык, которого в проекте нет, либо это пробел для `domain-modeling`.

## Конфликт с ADR

Вывод противоречит ADR — скажите об этом явно («Противоречит ADR-0007, но пересмотреть
стоит, потому что…»), а не переписывайте решение молча.
