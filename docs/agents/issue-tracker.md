# Трекер задач: GitHub

Задачи и спецификации этого репозитория живут в GitHub Issues. Все операции — через `gh` CLI.
Репозиторий `gh` определяет сам, если запущен внутри клона (по `git remote -v`).

**Язык — русский.** Заголовок, описание и комментарии issue пишутся по-русски; идентификаторы
кода (файлы, классы, методы, переменные окружения, команды) остаются в оригинале.

## Операции

- **Создать:** `gh issue create --title "..." --body-file <файл>`. Многострочное тело — только
  через файл или heredoc, не через `--body` со сложным текстом.
- **Прочитать:** `gh issue view <номер> --comments`
- **Список:** `gh issue list --state open --json number,title,body,labels`
- **Комментарий:** `gh issue comment <номер> --body-file <файл>`
- **Лейблы:** `gh issue edit <номер> --add-label "..."` / `--remove-label "..."`
- **Закрыть:** `gh issue close <номер> --comment "..."`

## Триаж не используется

Триаж-машина скилла `triage` в этом репозитории не применяется, лейблы `needs-triage`,
`needs-info`, `ready-for-agent`, `ready-for-human` заводить не нужно. Используются штатные
лейблы GitHub (`bug`, `enhancement`, `documentation`). Файла `docs/agents/triage-labels.md`
нет намеренно.

## PR как поверхность запросов: нет

_(Поставьте «да», если внешние PR должны попадать в очередь разбора наравне с issues.)_

У GitHub общее пространство номеров для issues и PR, поэтому голый `#42` может означать и то,
и другое: сначала `gh pr view 42`, при неудаче — `gh issue view 42`.

## Когда скилл говорит «опубликовать в трекер»

Завести GitHub issue. Работа по ней ведётся отдельной веткой и Pull Request — прямые коммиты
в `main` не делаются (см. «Правила ведения работы» в `CLAUDE.md`).

## Операции wayfinding

Используются скиллом `wayfinder`. Карта — одна issue с лейблом `wayfinder:map`, тикеты —
дочерние issues (GitHub sub-issues; где недоступны — список задач в теле карты и строка
`Part of #<карта>` в начале тела дочерней). Блокировки — нативные зависимости GitHub
(`gh api --method POST repos/<owner>/<repo>/issues/<n>/dependencies/blocked_by`), при
недоступности — строка `Blocked by: #<n>` в начале тела. Тикет свободен, когда все его
блокировщики закрыты.
